# Workout App — приложение-помощник для тренировок

Проект для поступления в магистратуру (CS/ML). Приложение генерирует тренировочные планы и адаптирует нагрузку на основе истории пользователя с помощью ML.

## Идея проекта

Пользователь вводит исходные данные (имя, опыт, дни в неделю) → приложение генерирует план тренировок под гипертрофию → пользователь логирует подходы (вес, повторения, RIR) → система рекомендует вес/повторения на следующую тренировку, адаптируясь под прогресс конкретного пользователя.

**Ключевое отличие от существующих решений (RP Hypertrophy App и др.):** большинство аналогов используют fixed rule-based автогуляцию (одинаковые правила для всех). Здесь — персонализированная ML-модель, дообучающаяся на истории конкретного пользователя, а не универсальные пороги.

## Related work / аналоги

- **RP Hypertrophy App (Renaissance Periodization)** — rule-based автогуляция на основе volume landmarks (MEV/MAV/MRV), RIR-based прогрессия. Прямой референс, но не ML.
- **Strong, Hevy, JEFIT** — трекеры без адаптивной логики нагрузки.
- **WorkoutAI** и подобные рус. приложения — генерация плана через ИИ/LLM, но без per-user адаптации на основе прогресса.
- На российском рынке решения с ML-персонализацией и RIR-based автогуляцией на момент анализа не найдено — свободная ниша.

## ML-подход

**Гибрид: rule-based холодный старт → per-user ML-дообучение**

- Первые ~3-4 недели (или N тренировок по упражнению, порог может быть per-exercise) — рекомендации по прозрачным правилам (double progression / RIR-based autoregulation)
- После накопления истории (например 8-10 сессий по упражнению) — источник рекомендации переключается на модель, дообученную персонально на данных конкретного пользователя
- Каждая рекомендация помечается источником (`rule_based` / `ml_model`) для прозрачности и последующей оценки качества (эту метку показываем и в интерфейсе — небольшой бейдж на карточке рекомендации)
- Защита от резких скачков нагрузки (жёсткий порог на максимальное % изменение веса за раз, поверх любой рекомендации — и rule-based, и ML)
- Объяснение каждой рекомендации простым текстом ("почему такой вес") — для доверия пользователя к системе

### Rule-based логика (double progression + RIR)
```
ЕСЛИ reps >= exercise.default_rep_range_max И rir >= целевой_RIR:
    новый_вес = текущий_вес + exercise.weight_increment
    новый_reps = exercise.default_rep_range_min  (сброс к низу диапазона)
ИНАЧЕ ЕСЛИ reps < exercise.default_rep_range_max И rir >= целевой_RIR:
    новый_вес = текущий_вес (без изменений)
    новый_reps = reps + 1
ИНАЧЕ (rir < целевого — было тяжело):
    новый_вес = текущий_вес
    новый_reps = reps (не форсировать прогресс)
```
Диапазон повторений и шаг веса берутся из полей конкретного упражнения (см. схему Exercise ниже), а не заданы глобально — потому что оптимальный диапазон сильно отличается по типу упражнения (крупные compound-движения обычно 4-12, мелкие изолирующие/выносливые мышцы вроде икр — 12-20+).

### ML-модель (после холодного старта)
На малых per-user данных (десятки точек, не тысячи) полноценные LSTM/RL скорее переобучатся, чем дадут пользу. Реалистичный путь для MVP — **регрессия/градиентный бустинг (XGBoost/LightGBM), а не нейросеть**, на признаках:
- Тренд последних N сессий (вес, повторения, RIR)
- Скользящее среднее RIR
- Дней с последней тренировки этого упражнения
- Недельный объём по мышечной группе
- Была ли предыдущая рекомендация принята или переопределена

LSTM/GRU или полноценный RL — оставлены как future work / research extension, когда будет достаточно данных (в том числе, возможно, агрегированных по многим пользователям).

## Функции MVP

### Онбординг
- Опыт тренировок (новичок / средний / продвинутый)
- Дни в неделю
- Цель (сила / гипертрофия / общая форма)
- Ограничения / травмы

### Генерация плана + логирование
- Автоматический сплит по дням на основе введённых данных
- База упражнений с фильтрами и возможностью замены
- Лог веса, повторений, RIR, заметок к подходу
- RIR — необязательное поле. По умолчанию открывается упрощённый выбор из 4
  текстовых формулировок ("мог сделать ещё много" / "ещё пару" / "максимум одно" /
  "до отказа" → конвертируются в RIR 4-5/2-3/1/0), а не голое число — снижает
  порог входа для новичков и ленивых пользователей. Есть опция "ввести точное
  число" для продвинутых. Минимальное значение RIR = 0 (нелогично отрицательное).
- Таймер отдыха между подходами — круглый (в духе iOS), тап по центру ставит
  на паузу (кольцо становится приглушённым, по центру иконка паузы вместо цифр)
- Warm-up сеты отдельно от рабочих (не влияют на прогрессию)

### ML-ядро
- Адаптивная рекомендация веса/повторений на следующую тренировку
- Объяснение рекомендации
- Возможность переопределить вручную (сигнал для модели)
- Защита от резких скачков нагрузки
- Учёт суммарного объёма по мышечной группе за неделю
- Детекция застоя (2+ недели без прогресса) → предложение изменений

### Контекст для модели
- Чек-ин самочувствия перед тренировкой (сон / энергия / стресс)

### Пресеты / мезоциклы
- Сохранение текущего плана как пресета
- Переключение между пресетами
- Deload-недели

### Вовлечённость
- PR-трофей при новом весе/повторении (можно отключить в настройках)
- Стрик тренировок
- Быстрый повтор прошлой тренировки

## Отложено на потом (не в MVP)
- Пресеты тренировок известных атлетов (CBum, Sam Sulek и т.д. — нужно решить вопрос прав на имя/образ перед реальным релизом)
- Социальные функции, лидерборды
- Интеграция с носимыми устройствами (пульс, сон, HRV)
- Компьютерное зрение для анализа техники
- Локализация на другие языки

## Схема данных

### User
```
- id
- name
- experience_level (beginner/intermediate/advanced)
- days_per_week
- limitations ([{body_part, note}])
- created_at
```
Поле `goal` убрано — продукт по умолчанию сфокусирован на гипертрофии (см. раздел "Позиционирование продукта").

### Exercise (справочник)
```
- id
- name
- muscle_group_primary
- muscle_group_secondary ([])
- equipment (barbell/dumbbell/machine/cable/bodyweight)
- difficulty (beginner/intermediate/advanced)
- movement_type (compound/isolation)
- default_rep_range_min / default_rep_range_max  (per-exercise, не общий диапазон:
  например 8-12 для жима, 12-20 для икр — мышцы растут в широком диапазоне 4-30,
  но оптимум разный по типу мышцы/движения)
- weight_increment  (минимальный шаг прогрессии веса, per-exercise: 1.25/2.5/5 кг —
  зависит от доступного оборудования, не единое правило "верх/низ тела")
- default_rest_seconds  (время отдыха между подходами по умолчанию: больше для
  крупных compound-движений типа приседа/тяги, меньше для изоляции; используется
  для расчёта примерной длительности тренировки на Home-экране, пока нет истории
  пользователя — после нескольких выполненных тренировок заменяется на реальное
  среднее из WorkoutSession.duration_minutes)
```

### Program (пресет плана)
```
- id
- user_id
- name
- mesocycle_type (strength/hypertrophy/deload...)
- created_at
- is_active
```

### ProgramDay
```
- id
- program_id
- day_order
- day_name
```

### ProgramExercise
```
- id
- program_day_id
- exercise_id
- order_in_day
- target_sets
- target_rep_range
```

### WorkoutSession (факт тренировки)
```
- id
- user_id
- program_day_id
- date
- readiness_checkin ({sleep, energy, stress})
- duration_minutes
```

### SetLog (запись подхода — основные данные для ML)
```
- id
- workout_session_id
- exercise_id
- set_number
- weight
- reps
- rir
- is_warmup
- note
- was_recommended
- recommended_weight / recommended_reps
```

### Recommendation
```
- id
- user_id
- exercise_id
- date
- recommended_weight
- recommended_reps
- reasoning
- source (rule_based / ml_model)
- accepted
```

**Логика разделения:** Program/ProgramDay/ProgramExercise — это план (что должно быть). WorkoutSession/SetLog — это факт (что реально было сделано). Разделение нужно для сравнения план vs реальность и для корректных данных под ML.

## UX-флоу (зафиксированные решения)

### Главный экран (Home)
<img width="1472" height="2020" alt="image" src="https://github.com/user-attachments/assets/73eb0752-4314-4776-9009-db4840f679c1" />

- Приветствие + дата, стрик тренировок, прогресс за неделю (X из Y тренировок)
- Центральный акцентный блок "Сегодня по плану" — название дня + кнопка "Начать тренировку"
- Кнопка "Повторить последнюю сессию" — отдельный от расписания путь: открывает
  точно тот же набор упражнений/весов, что были в последней завершённой сессии,
  вне зависимости от того, какой день плана "должен быть" сегодня по календарю.
  Полезно, если пользователь выбился из графика (пропустил день и т.д.)
- Нижняя навигация: Главная / Прогресс / Пресеты / Настройки
- Оценка длительности тренировки на карточке дня — не статичный текст: пока нет
  истории, считается по формуле (подходы × время выполнения + подходы × 
  default_rest_seconds по каждому упражнению); после нескольких выполненных
  тренировок этого дня — заменяется на реальное среднее из истории пользователя

### Экран дня тренировки
- Крупный заголовок дня (например "День груди") + прогресс-бар (2 из 5 выполнено)
- Список упражнений: выполненные — свёрнуты в компактную строку с результатами
  по подходам, текущее — активная карточка с рекомендацией и таблицей подходов,
  невыполненные — краткий превью с целевым диапазоном

### Immersive-режим упражнения
Тап на текущее упражнение → полноэкранный режим с максимальным фокусом:
- Карточка рекомендации (вес × повторения, reasoning-строка, бейдж источника
  rule_based/ml_model) + таблица всех подходов упражнения (разминка отдельно,
  выполненные — с галочкой, текущий — с полями ввода, будущие — приглушены)
- Поля ввода предзаполнены рекомендацией — пользователь либо просто подтверждает
  (если сделал столько же), либо корректирует вручную (= override, уходит в
  модель как сигнал)
- После "Записать подход" экран переключается на круглый таймер отдыха (не
  отдельный переход — то же место экрана, другое состояние). Таймер: тап по
  центру — пауза/возобновление, кнопки -15с/+15с/пропустить
- После отдыха — автовозврат к таблице подходов, следующая строка становится активной

## Научная база (источник: The Muscle Ladder, Jeff Nippard)

Используется как обоснование для rule-based ядра — конкретные ориентиры вместо абстрактных правил.

### Объёмные ориентиры по группам мышц (недельные рабочие подходы)
Дефолты для среднего/продвинутого уровня; новичкам — стартовать ближе к MEV/нижней MAV.
```
muscle_group_volume_landmarks = {
  "chest":     {mev: 8,  mav_low: 12, mav_high: 18, mrv: 22},
  "back":      {mev: 10, mav_low: 14, mav_high: 22, mrv: 25},
  "shoulders": {mev: 8,  mav_low: 12, mav_high: 20, mrv: 24},
  "quads":     {mev: 8,  mav_low: 12, mav_high: 18, mrv: 22},
  "hamstrings":{mev: 6,  mav_low: 10, mav_high: 15, mrv: 18},
  "glutes":    {mev: 8,  mav_low: 12, mav_high: 20, mrv: 24},
  "biceps":    {mev: 6,  mav_low: 10, mav_high: 16, mrv: 20},
  "triceps":   {mev: 6,  mav_low: 10, mav_high: 16, mrv: 20},
  "calves":    {mev: 6,  mav_low: 10, mav_high: 16, mrv: 20},
  "abs":       {mev: 0,  mav_low: 8,  mav_high: 16, mrv: 20},
}
```
Используется на экране прогресса (вкладка "Группы мышц") для сравнения факта с ориентиром, и позднее — как baseline, который ML уточняет персонально под пользователя.

### Формула deload
```python
def calculate_deload(current_weight, current_volume_sets, current_rpe):
    deload_weight = current_weight * (1 - 0.075)       # снижение веса на 5-10%
    deload_sets = round(current_volume_sets * (1 - 0.4))  # снижение объёма на 30-50%
    deload_rpe_target = current_rpe - 2                 # снижение интенсивности на 1-3 пункта RPE
    return deload_weight, deload_sets, deload_rpe_target
```

### Реакция на застой — последовательность стратегий, не одна
Смена упражнения — последний вариант в очереди, а не первый (в отличие от изначальной логики).
```python
plateau_strategies = [
    "increase_load",        # добавить вес
    "increase_reps",        # добавить повторения при том же весе
    "add_set",               # добавить подход
    "reduce_rest_time",      # сократить отдых между подходами
    "improve_mind_muscle",   # текстовая подсказка про технику/фокус на мышце
    "increase_velocity",     # ускорить концентрическую фазу
    "beyond_failure",        # дроп-сеты и т.п. — только для продвинутых
    "swap_exercise",         # смена упражнения — последний вариант
]
# при детекции застоя (>= 2 недель без прогресса) перебираем стратегии по кругу,
# отслеживая, что уже пробовали для этого упражнения у этого пользователя
```

### Ротация упражнений — привязка к опыту
```python
exercise_rotation_months = {
    "beginner": (3, 6),
    "intermediate": (2, 4),
    "advanced": (2, 6),   # чаще сталкиваются с плато, но разброс шире
}
```
Влияет на частоту предложений сменить упражнение (не только реакция на застой, но и профилактическая ротация).

### Целевое распределение диапазонов повторений в недельном плане
```python
rep_range_distribution_target = {
    "low (1-5 reps)": (0.10, 0.20),
    "moderate (6-15 reps)": (0.60, 0.80),
    "high (15-30 reps)": (0.10, 0.20),
}
```
Генератор плана должен проверять, что итоговая структура недели укладывается в эти пропорции, а не ставить один и тот же диапазон повторений на каждое упражнение без учёта общего баланса.

## Позиционирование продукта

**Приложение сфокусировано конкретно на гипертрофии/бодибилдинге**, а не на универсальной поддержке разных целей (сила, общая форма и т.д.). Причины:
- Личная экспертиза автора именно в тренировках на массу, не в силовых показателях
- Вся научная база из книги Ниппарда (объёмные ориентиры, диапазоны повторений, deload-формула — см. раздел ниже) написана под гипертрофию, без нужды адаптировать под другие цели
- Более чёткий research scope для заявки — не размытый "универсальный фитнес-помощник"
- Упрощает и rule-based логику (не нужно разветвлять формулы прогрессии под разные цели), и онбординг (шаг "Цель" не нужен)

### Онбординг (обновлённая последовательность)
0. **Имя** — для персонализации (используется на Home-экране: "Привет, {имя}" и в reasoning-текстах рекомендаций)
1. Опыт тренировок (новичок/средний/продвинутый, с пояснением стажа под каждым)
2. Дни в неделю (слайдер с числом 2-6, не выбор конкретных дней календаря — см. пункт про очередь тренировок в открытых вопросах)
3. ~~Цель~~ — убрано, продукт по умолчанию заточен под гипертрофию
4. Ограничения/травмы (теги частых зон + свободный комментарий, явно помечено "можно пропустить")
5. Генерация плана (короткий лоадер + summary выбранных параметров)
