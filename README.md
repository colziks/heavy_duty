# Workout App — приложение-помощник для тренировок

Проект для поступления в магистратуру (CS/ML). Приложение генерирует тренировочные планы под гипертрофию и адаптирует нагрузку на основе истории пользователя с помощью ML.

## Идея проекта

Пользователь вводит исходные данные (имя, опыт, дни в неделю) → приложение генерирует план тренировок под гипертрофию → пользователь логирует подходы (вес, повторения, RIR) → система рекомендует вес/повторения на следующую тренировку, адаптируясь под прогресс конкретного пользователя.

**Ключевое отличие от существующих решений (RP Hypertrophy App и др.):** большинство аналогов используют fixed rule-based автогуляцию (одинаковые правила для всех). Здесь — персонализированная ML-модель, дообучающаяся на истории конкретного пользователя, а не универсальные пороги.

Аккаунт создаётся автоматически и анонимно при первом запуске (без обязательной регистрации/логина) — пользователь сразу попадает в онбординг и может пользоваться приложением. Привязка email/пароля — опциональная функция на будущее (для сохранения прогресса при смене телефона), доступна из настроек, не блокирует старт использования.

## Related work / аналоги

- **RP Hypertrophy App (Renaissance Periodization)** — rule-based автогуляция на основе volume landmarks (MEV/MAV/MRV), RIR-based прогрессия. Прямой референс, но не ML.
- **Strong, Hevy, JEFIT** — трекеры без адаптивной логики нагрузки.
- **WorkoutAI** и подобные рус. приложения — генерация плана через ИИ/LLM, но без per-user адаптации на основе прогресса.
- На российском рынке решения с ML-персонализацией и RIR-based автогуляцией на момент анализа не найдено — свободная ниша.

## Научные источники

- **The Muscle Ladder** — Jeff Nippard. Основной источник объёмных ориентиров по группам мышц и общей структуры принципов (иерархия "Muscle Ladder").
- **The Muscle & Strength Pyramid: Training** — Eric Helms, Andy Morgan, Andrea Valdez. Источник для rule-based логики (double progression, deload-протоколы по опыту, RPE/RIR-шкала).
- **Scientific Principles of Hypertrophy Training** — Mike Israetel, James Hoffmann, Melissa Davis (Renaissance Periodization). Первоисточник концепции volume landmarks (MEV/MAV/MRV).

**Сверка проведена честно:** термины MEV/MAV/MRV и наши числовые ориентиры по группам мышц подтверждены напрямую в этих источниках, не выдуманы. Rule-based логика double progression практически дословно совпадает с методологией Хелмса. Обнаруженная и исправленная неточность — см. "Формула deload" ниже.

## Валидация на реальных данных пользователя

Проанализированы два лога собственных тренировок автора (лето 2024 – март 2025, апрель – август 2026). Ключевые находки:

- **Rule-based ядро (double progression) подтверждено независимо** — реальная многолетняя практика автора почти учебниково следует той же логике, что заложена в README, безо всякой подгонки.
- **Deload — сильный аргумент в пользу персонализации, а не жёстких правил по опыту.** Автор (продвинутый уровень) использовал свой протокол (снижение веса ~40%, объём/повторения без изменений, по ситуативному ощущению усталости) — это не совпадает ни с одним из двух протоколов Хелмса (новичок: только вес -10%; средний/продвинутый: только объём -50%). Живое доказательство, что даже в рамках одного уровня опыта оптимальный протокол индивидуален — ключевой аргумент для ML-персонализации, а не для дальнейшего усложнения rule-based ветвления по опыту.
- **Признак "дней с последней тренировки упражнения" — не опциональный, а обязательный.** После 4-недельного перерыва (отпуск без тренировок) показатели по всем упражнениям заметно просели (например, присед 70→62.5 кг, RDL 67.5→60 кг). Модель без этого признака рекомендовала бы продолжить прогрессию от последнего рабочего веса, что было бы неверной и потенциально небезопасной рекомендацией.
- **Задние дельты и ягодицы не тренировались напрямую** (расчёт на непрямую стимуляцию от тяг/RDL) — по объёмным ориентирам это рискованная зона (может не набирать MEV). Основание для добавления информационной проверки в генератор плана (см. ниже).

## ML-подход

**Плавное смешивание популяционной и персональной модели (empirical Bayes / shrinkage), а не жёсткое переключение rule-based → ML.**

Изначальный план (rule-based первые недели → переключение на ML после накопления истории) имел проблему: первые 3-4 недели пользователь не видел вообще никакого ML — только формулы, и реальная адаптация становилась заметна слишком поздно относительно того, что заявлено в позиционировании продукта.

**Как работает сейчас:**
- **Популяционная модель** — обучается один раз офлайн на синтетических данных: симулируем множество "виртуальных пользователей", следующих rule-based логике (double progression) с реалистичным шумом (пропуски, застои, вариативность RIR), и обучаем регрессию/бустинг на этих траекториях
- **Персональная модель** — та же архитектура, дообучается только на реальных данных конкретного пользователя по мере накопления истории
- **Смешивание через вес доверия, растущий с числом сессий:**
```python
w_personal = n_sessions / (n_sessions + k)   # k — константа сглаживания, например 8
итоговая_рекомендация = w_personal * персональная_модель + (1 - w_personal) * популяционная_модель
```
При `n_sessions = 0` рекомендация почти полностью на популяционной модели (это уже ML, не rule-based формула, просто без персонализации). С каждой тренировкой вес плавно сдвигается к персональной модели — без резкого переключения.

**Что это даёт:** с первого дня пользователь получает именно ML-рекомендацию (просто основанную на общих паттернах, а не персональных), а не "калькулятор, который через месяц станет умным". Честнее по отношению к пользователю и сильнее методологически для заявки — это не разделение "правила vs модель", а empirical Bayes с population prior, постепенно замещаемым персональным сигналом.

- Объяснение каждой рекомендации простым текстом ("почему такой вес") — для доверия пользователя к системе
- Защита от резких скачков нагрузки (жёсткий порог на максимальное % изменение веса за раз, поверх итоговой смешанной рекомендации)
- Интерфейс отражает степень персонализации не бинарным бейджем (`rule_based`/`ml_model`), а плавным индикатором: "Общие паттерны" → "Калибруется" → "Персонализировано" (по значению `w_personal`)

### Rule-based логика (double progression + RIR) — используется для генерации синтетических данных популяционной модели
```
ЕСЛИ reps >= exercise.default_rep_range_max И rir >= целевой_RIR:
    шаг = next(exercise.weight_increment_sequence)  (по кругу, microloading)
    новый_вес = текущий_вес + шаг
    новый_reps = exercise.default_rep_range_min  (сброс к низу диапазона)
ИНАЧЕ ЕСЛИ reps < exercise.default_rep_range_max И rir >= целевой_RIR:
    новый_вес = текущий_вес (без изменений)
    новый_reps = reps + 1
ИНАЧЕ (rir < целевого — было тяжело):
    новый_вес = текущий_вес
    новый_reps = reps (не форсировать прогресс)
```

**Fallback без RIR** (когда пользователь выключил отслеживание RIR в настройках) — чистая двойная прогрессия по повторениям, без условия по RIR. Подтверждено собственной практикой автора — годами применялось именно так, RIR не фиксировался вовсе:
```
ЕСЛИ reps >= exercise.default_rep_range_max:
    шаг = next(exercise.weight_increment_sequence)
    новый_вес = текущий_вес + шаг
    новый_reps = exercise.default_rep_range_min
ИНАЧЕ:
    новый_вес = текущий_вес
    новый_reps = reps + 1
```
Раньше эта логика была основным механизмом рекомендаций на старте; теперь используется как правило для симуляции синтетических "виртуальных пользователей" при обучении популяционной модели (обе версии — с RIR и без — генерируют часть синтетических пользователей, пропорционально ожидаемой доле реальных пользователей, отключающих RIR), а не напрямую для рекомендаций.

### ML-модель
На малых per-user данных (десятки точек, не тысячи) полноценные LSTM/RL скорее переобучатся, чем дадут пользу. Реалистичный путь для MVP — **регрессия/градиентный бустинг (XGBoost/LightGBM), а не нейросеть**, на признаках:
- Тренд последних N сессий (вес, повторения, RIR)
- Скользящее среднее RIR
- **Дней с последней тренировки этого упражнения — критичный признак, не опциональный.** Подтверждено реальными данными: после многонедельного перерыва показатели заметно падают (см. "Валидация на реальных данных" выше); без этого признака модель рекомендовала бы продолжение прогрессии вслепую, что небезопасно
- Недельный объём по мышечной группе
- Была ли предыдущая рекомендация принята или переопределена

LSTM/GRU или полноценный RL — оставлены как future work / research extension, когда будет достаточно данных.

## Позиционирование продукта

**Приложение сфокусировано конкретно на гипертрофии/бодибилдинге**, а не на универсальной поддержке разных целей (сила, общая форма и т.д.). Причины:
- Личная экспертиза автора именно в тренировках на массу, не в силовых показателях
- Вся научная база (объёмные ориентиры, диапазоны повторений, deload) написана под гипертрофию
- Более чёткий research scope для заявки
- Упрощает rule-based логику и онбординг (шаг "Цель" не нужен)

## Функции MVP

### Онбординг (актуальная последовательность)
0. **Welcome-экран** — название приложения, короткий слоган, кнопка "Начать" (без логина)
1. **Имя** — для персонализации (используется на Home: "Привет, {имя}" и в reasoning-текстах рекомендаций)
2. **Опыт тренировок** (новичок/средний/продвинутый, с пояснением стажа под каждым — "меньше 1 года" / "1-3 года" / "3+ года")
3. **Дни в неделю** (слайдер с числом 2-6, НЕ выбор конкретных дней календаря — см. "Логика очереди тренировок" ниже)
4. **PR-трофеи** — короткий опциональный вопрос "показывать поздравления при новых рекордах?" (да/нет), решение можно поменять позже в настройках
5. **Генерация плана** (короткий лоадер + summary выбранных параметров)

Убрано из онбординга: шаг "Цель" (продукт заточен под гипертрофию по умолчанию), шаг "Ограничения/травмы" (см. "Избегаемые упражнения" ниже — заменено более простым и честным механизмом), обязательный логин.

### Генерация плана + логирование
- Автоматический сплит по дням на основе введённых данных
- База упражнений с фильтрами (по группе мышц, оборудованию) и возможностью замены/добавления — см. `exercises_seed.csv`, 68 упражнений по 10 группам мышц, поля соответствуют схеме Exercise
- **Проверка покрытия групп мышц** (информационная, не блокирующая): если в плане нет ни одного прямого упражнения на группу мышц, которая обычно недополучает стимуляцию только от непрямой работы (типичные случаи — задние дельты, ягодицы), показать мягкое предупреждение при генерации/редактировании плана — не запрещать, просто уведомить. Основание: реальный пример в собственных логах автора, где непрямая работа не гарантированно закрывала MEV.
- Лог веса, повторений, RIR, заметок к подходу
- RIR — необязательное поле, с полным переключателем "Отслеживать RIR" в настройках (вкл/выкл), не только "оставить пустым каждый раз". По умолчанию, если включено — открывается упрощённый выбор из 4 текстовых формулировок ("мог сделать ещё много" / "ещё пару" / "максимум одно" / "до отказа" → RIR 4-5/2-3/1/0). Опция "ввести точное число" для продвинутых. Минимум RIR = 0. Если отслеживание выключено полностью — поле RIR не показывается в интерфейсе вообще, rule-based/ML переходят на fallback-логику чистой двойной прогрессии без учёта RIR (см. ниже) — подтверждено собственной многолетней практикой автора, где RIR не фиксировался вовсе, а прогрессия шла по чистому достижению верха диапазона повторений.
- Таймер отдыха между подходами — круглый (в духе iOS), тап по центру — пауза/возобновление (кольцо становится приглушённым, иконка паузы вместо цифр), кнопки -15с/+15с/пропустить
- Warm-up сеты отдельно от рабочих (не влияют на прогрессию)
- **Очередь тренировок:** план НЕ привязан к дням недели календаря. "Начать тренировку" = следующая невыполненная тренировка в последовательности (по `day_order` в ProgramDay), не "сегодняшний день по расписанию". Пропуск тренировки сдвигает очередь, а не теряет/ломает часть недельного плана. "Повторить последнюю сессию" — отдельная функция (дублирует последнюю завершённую сессию вне очереди), не связана с логикой наверстывания.

### ML-ядро
- Адаптивная рекомендация веса/повторений на следующую тренировку
- Объяснение рекомендации
- Возможность переопределить вручную (сигнал для модели)
- Защита от резких скачков нагрузки
- Учёт суммарного объёма по мышечной группе за неделю
- Детекция застоя (2+ недели без прогресса) → последовательность из 8 стратегий (см. научную базу), смена упражнения — последний вариант, не первый

### Избегаемые упражнения (замена раздела "Ограничения/травмы")
Приложение не пытается интерпретировать травмы/ограничения и решать, что "безопасно" — одна и та же травма может по-разному ощущаться у разных людей, и такая псевдо-медицинская логика создавала бы ложное чувство безопасности. Вместо этого — простой личный список: пользователь может пометить любое упражнение как "не показывать мне" (из каталога или экрана замены), и генератор плана никогда не предлагает его снова. Переиспользует уже существующую механику замены/каталога упражнений, а не отдельную систему.

### Пресеты / мезоциклы
- Сохранение текущего плана как пресета
- Переключение между пресетами
- Типы мезоцикла: **Накопление объёма** ("больше подходов, растим объём тренировок"), **Интенсификация** ("тяжелее веса, меньше запас повторений"), **Разгрузка** ("неделя отдыха — меньше нагрузка, больше восстановление"). Каждый тип — с понятной подписью под названием, не просто термином. Тип "Специализация" — отложен в бэклог (см. ниже).
- Три способа создать пресет: сгенерировать автоматически / дублировать существующий и изменить / собрать вручную (конструктор по дням с добавлением упражнений из каталога)
- Индикатор прогресса внутри активного мезоцикла (неделя N из M до deload)

### Вовлечённость
- PR-трофей при новом весе/повторении — короткая модалка сразу в момент рекорда (не в конце тренировки), с сравнением к предыдущему результату. Спрашивается при онбординге (вкл/выкл), меняется в настройках.
- Стрик тренировок
- Быстрый повтор прошлой тренировки
- Финальная сводка тренировки (после явного нажатия "Завершить тренировку", не автоматически): длительность, количество подходов, список всех PR за сессию, обновлённый стрик, и сравнение недельного объёма по проработанным сегодня группам мышц с ориентирами MEV/MAV/MRV

## Отложено на потом (не в MVP)
- Тип мезоцикла "Специализация" (повышенный объём на отстающую группу мышц)
- Пресеты тренировок известных атлетов (CBum, Sam Sulek и т.д. — нужно решить вопрос прав на имя/образ перед реальным релизом)
- Социальные функции, лидерборды
- Интеграция с носимыми устройствами (пульс, сон, HRV)
- Компьютерное зрение для анализа техники
- Локализация на другие языки
- Обязательная авторизация с самого начала (сейчас — анонимный аккаунт с опциональной привязкой)

## Схема данных

### User
```
- id
- name
- experience_level (beginner/intermediate/advanced)
- days_per_week
- show_pr_trophies (bool, спрашивается при онбординге)
- created_at
```
Поля `goal` и `limitations` убраны. `goal` — продукт сфокусирован на гипертрофии по умолчанию. `limitations` заменено на отдельную сущность HiddenExercise (см. ниже) — честнее, чем псевдо-медицинская интерпретация тегов травм.

### HiddenExercise (замена поля limitations)
```
- id
- user_id
- exercise_id
- created_at
```
Простая связь user → exercise, которые пользователь пометил "не показывать". Генератор плана и каталог исключают эти exercise_id для данного user_id.

### Exercise (справочник)
```
- id
- name
- muscle_group_primary
- muscle_group_secondary ([])
- equipment (barbell/dumbbell/machine/cable/bodyweight)
- difficulty (beginner/intermediate/advanced)
- movement_type (compound/isolation)
- default_rep_range_min / default_rep_range_max  (per-exercise, не общий диапазон)
- weight_increment_sequence  (шаг прогрессии веса — **определяется физическим
  ограничением оборудования, не произвольным выбором**:
  - `barbell` (штанга) — блины навешиваются с двух сторон одновременно, шаг
    всегда кратен весу блина ×2; реалистичный минимум — 2.5 кг за раз, дробить
    нельзя (довесить один блин на одну сторону — не вариант, штанга перекосится)
  - `dumbbell` (гантели) — фиксированные заводские снаряды, нельзя "довесить";
    берётся следующая по весу с полки, обычно шаг 2.5 кг (15 → 17.5 → 20)
  - `machine`/`cable` (тренажёры/блоки) — можно самостоятельно докинуть
    небольшой съёмный блин поверх выбранного веса на стеке, поэтому здесь
    реалистична microloading-прогрессия мелким шагом (1.25 кг)
  - `bodyweight` — не применимо, отдельная механика прогрессии (не в MVP)
  
  См. `exercises_seed.csv` — значения пересчитаны по этому принципу для всех
  68 упражнений)
- default_rest_seconds  (время отдыха между подходами по умолчанию; используется
  для расчёта примерной длительности тренировки на Home-экране, пока нет истории —
  после нескольких выполненных тренировок заменяется на реальное среднее из
  WorkoutSession.duration_minutes)
```
Посевные данные (68 упражнений, 10 групп мышц, все типы оборудования): `exercises_seed.csv` — использовать как основу для каталога упражнений на этапе реализации.

## UX-флоу (зафиксированные решения)

**Важное примечание про мокапы:** помимо детальных мокапов каждого экрана (созданных по ходу обсуждения и описанных ниже), в чате также показывалась общая обзорная галерея со всеми экранами сразу для удобства навигации по структуре приложения. Галерея — упрощённые превью (убраны часть деталей: дополнительные метрики, подписи осей графиков, второстепенные элементы) ради компактности показа, а НЕ финальная версия экранов. Источник истины по деталям каждого экрана — отдельные полноразмерные мокапы и описания в этом файле, а не обзорная галерея.

### Welcome → Онбординг
См. последовательность в разделе "Функции MVP" выше.

### Главный экран (Home)
- Приветствие по имени + дата, стрик тренировок, прогресс за неделю (X из Y тренировок)
- Центральный акцентный блок "Сегодня по плану" — название дня + кнопка "Начать тренировку" (следующая по очереди, см. day_order)
- Кнопка "Повторить последнюю сессию"
- Нижняя навигация: Главная / Прогресс / Пресеты / Настройки
- Оценка длительности тренировки — не статичный текст: пока нет истории, считается по формуле (подходы × время выполнения + default_rest_seconds по каждому упражнению), дальше заменяется реальным средним по истории пользователя

### Экран дня тренировки
- Крупный заголовок дня + прогресс-бар (N из M выполнено)
- Список упражнений: выполненные — свёрнуты с результатами по подходам, текущее — активная карточка, невыполненные — краткий превью с целевым диапазоном
- У каждого невыполненного упражнения — маленькая иконка замены (⇄) на карточке (не модалка при каждом тапе — навязчиво). Тап по самой карточке — начинает упражнение, тап по иконке — открывает список замен
- Когда все упражнения выполнены — кнопки "Добавить ещё упражнение" и "Завершить тренировку" (явное действие, не автопереход)

### Immersive-режим упражнения
Тап на упражнение → полноэкранный режим с максимальным фокусом:
- Карточка рекомендации (вес × повторения, reasoning-строка, бейдж степени персонализации — "Общие паттерны" / "Калибруется" / "Персонализировано") + таблица всех подходов (разминка отдельно, выполненные — с галочкой, текущий — с полями ввода, будущие — приглушены)
- Поля ввода предзаполнены рекомендацией — подтвердить или скорректировать (override → сигнал модели)
- После "Записать подход" — переключение на круглый таймер отдыха (то же место экрана, другое состояние: тап по центру — пауза, кнопки -15с/+15с/пропустить)
- После отдыха — автовозврат к таблице, следующая строка активна

### Завершение тренировки
- **PR-модалка** — короткая, появляется сразу в момент рекорда (не откладывается до конца тренировки): трофей, название упражнения, новый результат vs предыдущий, кнопка "Продолжить"
- **Финальная сводка** (после явного "Завершить тренировку" на экране дня): длительность, количество подходов, новые PR за сессию списком, недельный объём по проработанным сегодня группам мышц относительно MEV/MAV/MRV, обновлённый стрик

### Экран прогресса — 3 вкладки
- **Упражнения** — выбор упражнения, метрики (текущий вес / изменение за период / рекорд), график с точками и сеткой (размер точки = объём подхода), список последних сессий
- **Группы мышц** — недельный объём (подходы) по каждой группе с цветовой индикацией относительно MEV/MAV/MRV
- **История** — общие метрики (тренировок всего, стрик, среднее время), список сессий по датам с кратким summary, PR-метка у тренировок с рекордами, **пропущенные тренировки тоже показаны** (приглушённо, честная картина, а не только успехи)

### Пресеты/мезоциклы
- Активный пресет — карточка сверху с прогрессом мезоцикла (неделя N из M, дней до deload)
- Список сохранённых пресетов ниже
- Кнопка создания нового → выбор названия, типа мезоцикла (с понятными подписями), дней в неделю, способа сборки (автоматически / дублировать / вручную)
- Конструктор вручную — табы по дням, список упражнений с drag-иконкой (порядок), редактированием подходов/повторений, удалением; кнопка "Добавить упражнение" открывает каталог; нижняя сводка — количество упражнений/подходов и распределение по группам мышц
- Каталог упражнений (используется и для добавления, и для замены) — поиск, сетка групп мышц для навигации, список с фильтрами по оборудованию

### Настройки
- Профиль (имя, опыт, дни в неделю — с предупреждением, что смена дней может потребовать пересборки плана)
- Раздел "Тренировки": единицы измерения (кг/фунты), переключатель "Отслеживать RIR" (вкл/выкл — полностью убирает поле из интерфейса при выключении; при выключении показывается короткая bottom sheet с честным пояснением trade-off'а: "Рекомендации будут чуть менее чувствительны к тому, как тяжело прошёл подход. Прогрессия продолжит работать по весу и повторениям. Можно включить обратно в любой момент" — не блокирует решение, просто информирует), при включённом — дополнительный переключатель точного числового ввода вместо упрощённого текстового выбора
- Раздел "Вовлечённость": тумблер PR-трофеев
- Раздел "Приложение": уведомления (на будущее), язык (заглушка), экспорт данных
- Раздел "Аккаунт": привязать аккаунт (опционально, не обязательно), выйти, удалить аккаунт, версия приложения

### Формула deload — ИСПРАВЛЕНО (разделение по опыту, по Хелмсу)
Первая версия смешивала два разных метода из источника (снижение и веса, и объёма одновременно) — неточность, найденная при сверке с оригиналом. Хелмс явно разделяет протокол по training age:
- **Новички:** только снижение интенсивности на 10%, объём (подходы/повторения) не трогаем
- **Средний/продвинутый:** только снижение объёма (примерно вдвое — убрать 1-2 подхода с упражнения, снизить повторения на ~2), вес остаётся тем же, RPE падает как следствие примерно на 2 пункта
```python
def calculate_deload(experience_level, current_weight, current_sets, current_reps, current_rpe):
    if experience_level == "beginner":
        return current_weight * 0.9, current_sets, current_reps, current_rpe
    else:
        return current_weight, round(current_sets * 0.5), current_reps - 2, current_rpe - 2
```

## Статус реализации (прототип)

Помимо проектирования, начата реальная разработка — рабочий локальный backend-прототип (`main.py`), который можно запустить и потрогать руками.

**Фактически используемый стек в прототипе:** FastAPI + SQLite (вместо PostgreSQL из финального плана — SQLite выбран для локальной разработки/обучения, не требует отдельной установки сервера БД; переход на PostgreSQL — минимальные изменения в коде благодаря SQLAlchemy).

**Реализовано и протестировано end-to-end:**
- Таблицы: User, Exercise (с загрузкой из `exercises_seed.csv` при первом запуске), Program, ProgramDay, ProgramExercise, WorkoutSession, SetLog
- Rule-based рекомендация (double progression) — эндпоинт `POST /sets`
- **Логика очереди тренировок (`day_order`) — проверена вручную через `/docs` от начала до конца**: создание пользователя → программы → двух дней → упражнения → проверка, что первая тренировка выдаётся по очереди → завершение сессии → проверка, что следующей предлагается именно следующий день по очереди, а не тот же самый и не по календарю. Работает корректно.
- Постоянное хранение данных — подтверждено, что данные переживают перезапуск сервера (не только в памяти процесса)

**Сознательно упрощено в прототипе (не implementировано ещё):**
- `weight_increment` в текущем коде — одно число на упражнение (не альтернирующая последовательность `weight_increment_sequence`, которая описана в дизайне выше)
- Таблицы Recommendation и HiddenExercise — ещё не добавлены
- Никакой ML-части — только rule-based
- Никакой авторизации — `user_id` передаётся в запросах открыто

**Известная техническая ловушка (на будущее):** в FastAPI + SQLAlchemy, если после `db.commit()` не вызвать `db.refresh(object)`, эндпоинт может вернуть пустой `{}` вместо реальных данных — commit "сбрасывает" закешированные поля объекта, и без refresh они не подгружаются заново при формировании ответа. Столкнулись с этим на практике в эндпоинте `complete_session`, исправлено.

### Как запустить прототип локально
1. VS Code + расширение Python + виртуальное окружение (`.venv`)
2. `pip install fastapi uvicorn sqlalchemy`
3. Положить `main.py` и `exercises_seed.csv` в одну папку
4. `uvicorn main:app --reload`
5. Открыть `http://127.0.0.1:8000/docs` — интерактивная документация со всеми эндпоинтами
